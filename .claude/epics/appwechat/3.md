## Technical Requirements

### QR Code Format
```json
{
  "deviceId": "unique-device-identifier",
  "deviceType": "storytelling-toy",
  "serialNumber": "ST-2024-001234",
  "securityToken": "device-specific-token",
  "version": "1.0"
}
```

### Mini-Program Scanner Interface
```javascript
// QR code scanning implementation
const deviceScanner = {
  scanQRCode: () => {
    return wx.scanCode({
      scanType: ['qrCode'],
      onlyFromCamera: true
    });
  },
  
  discoverBLEDevices: () => {
    return wx.startBluetoothDevicesDiscovery({
      services: ['FFF0'], // Custom service UUID
      allowDuplicatesKey: false
    });
  }
};
```

### Backend API Specification
```
POST /device/pair
Headers: {
  "Authorization": "Bearer <jwt-token>"
}
Request: {
  "qrData": "scanned QR code data",
  "bleDeviceId": "BLE device MAC/ID",
  "deviceName": "user-friendly device name"
}
Response: {
  "success": true,
  "device": {
    "id": "device-uuid",
    "name": "My StorySpark Toy",
    "serialNumber": "ST-2024-001234",
    "pairedAt": "2025-09-10T09:16:37Z",
    "status": "connected"
  }
}
```

### Database Schema
```sql
-- Devices table
devices (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  serial_number VARCHAR(50) UNIQUE NOT NULL,
  device_type VARCHAR(50) NOT NULL DEFAULT 'storytelling-toy',
  security_token VARCHAR(255) NOT NULL,
  manufacturer_data JSONB,
  created_at TIMESTAMP DEFAULT NOW()
);

-- User-Device associations
user_devices (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  device_id UUID REFERENCES devices(id),
  device_name VARCHAR(100) NOT NULL,
  ble_device_id VARCHAR(100),
  paired_at TIMESTAMP DEFAULT NOW(),
  last_connected TIMESTAMP,
  status VARCHAR(20) DEFAULT 'paired',
  UNIQUE(user_id) -- Enforce one device per user
);
```

## Implementation Notes

### QR Code Security
- Implement QR code signature verification
- Use time-based tokens to prevent replay attacks
- Validate device serial numbers against manufacturer database
- Encrypt sensitive device information in QR codes

### BLE Device Discovery
- Filter devices by manufacturer data or service UUIDs
- Handle BLE adapter state changes
- Implement timeout for device discovery
- Cache discovered devices temporarily

### One-Toy-Per-User Logic
- Enforce database constraint on user_devices table
- Handle device transfer scenarios (unpair before re-pair)
- Provide clear error messages for pairing conflicts
- Allow admin override for special cases

### Error Scenarios
- QR code scanning failures (camera permission, invalid format)
- BLE discovery failures (Bluetooth disabled, no devices found)
- Device already paired to another user
- Network connectivity issues during pairing
